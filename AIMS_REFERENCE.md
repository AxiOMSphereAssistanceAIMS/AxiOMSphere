# AIMS ↔ ISO 55001 — справочник

## Файлы данных

| Файл | Назначение |
|------|------------|
| `ops/aims_element_hierarchy.json` | Иерархия элементов **E01–E23** (узлы 1.1, 1.1.1 … внутри каждого элемента). |
| `ops/aims_iso55001_detailed_clause_mapping.json` | Детальное сопоставление **ISO 55001** (разделы 1–10, подпункты 4.1–10.3) ↔ элементы AIMS, матрица, сквозные элементы. |
| `aims_iso55001_full_mapping.json` | Полная маршрутизация **P00–P07**, ключевые слова, матрица 4–10 (если используется в проекте). |

Пересборка JSON из кода: `python ops/build_aims_knowledge.py`

## P-коды ↔ раздел ISO 55001

| P-код | Раздел ISO 55001 | Тема (HLS) |
|-------|------------------|------------|
| **P00** | *(нет прямого раздела)* | Общий / смешанный контекст |
| **P01** | **4** | Контекст организации |
| **P02** | **5** | Лидерство |
| **P03** | **6** | Планирование |
| **P04** | **7** | Поддержка (ресурсы, компетенции, коммуникации, документированная информация) |
| **P05** | **8** | Операционная деятельность |
| **P06** | **9** | Оценка результатов |
| **P07** | **10** | Улучшение |

Разделы **1–3** ISO 55001 (область применения, нормативные ссылки, термины) **не** имеют отдельного P-кода; они поддерживают все элементы или отдельные элементы (см. детальный JSON).

## Заметки по глубине и выравниванию

- Иерархия внутри элементов **1–23** отражает темы HLS (контекст → лидерство → планирование → поддержка → операции → оценка → улучшение); **самый глубокий уровень** — практические исполнимые активности.
- Модель из **23 элементов** — детальная операционная декомпозиция **ISO 55001** с расширением разделов **8** (операции) и **9–10** (оценка и улучшение), в духе **ISO 55002** для сложных отраслей (нефтегаз, инфраструктура) и согласуема с **EAM/CMMS**.

---

## Нумерация в `aims_element_hierarchy.json`

Коды вида **1.1**, **1.1.1** относятся к **подразделам внутри каждого элемента AIMS** (например, Element 1 — Policy), а **не** к номерам пунктов ISO 55001.

## Интеграция в `ops/axi_bot.py` (Telegram)

При **`AXI_AIMS_KNOWLEDGE_IN_PROMPT=1`** бот **может** подмешивать в system prompt к Gemini/Anthropic большой справочник ISO/AIMS. Чтобы модель **не считала**, что она «только про AIMS», по умолчанию используется **`AXI_AIMS_KNOWLEDGE_MODE=on_topic`**: каталог добавляется **только если** вопрос (или контекст задачи/OCR) выглядит по теме ISO/AIMS/P-кодов/чата с документами. Для **старого поведения** (каталог в каждом сообщении) задайте **`AXI_AIMS_KNOWLEDGE_MODE=always`**.

В блок входят:

- правило **языка ответа** для темы ISO/AIMS: отвечать **на том же языке, на котором задан вопрос**;
- дерево **ISO 55001 разделы 1–10** с подпунктами и привязкой к **id элементов AIMS (1–23)**;
- таблицу **P00–P07 ↔ ISO 4–10**;
- матрицу и сквозные элементы;
- **полную внутреннюю иерархию E01–E23** из `aims_element_hierarchy.json`.

Переменные окружения:

| Переменная | Назначение |
|------------|------------|
| `AXI_AIMS_KNOWLEDGE_IN_PROMPT` | `1` / `0` — разрешить подмешивание справочника (при `0` каталог не добавляется). |
| `AXI_AIMS_KNOWLEDGE_MODE` | `on_topic` (по умолчанию) — только по релевантным вопросам; `always` — всегда; `off` — никогда. |
| `AXI_AIMS_KNOWLEDGE_MAX_CHARS` | Макс. длина блока (по умолчанию `62000`). |
| `AXI_AIMS_ELEMENT_HIERARCHY_JSON` | Путь к `aims_element_hierarchy.json` (если не рядом с ботом). |
| `AXI_AIMS_DETAILED_ISO_JSON` | Путь к `aims_iso55001_detailed_clause_mapping.json`. |

Классификация документов через OpenAI (`_openai_iso_aims_analyze`) дополнительно получает **`iso55001_clauses_detailed`** и урезанный **`aims_element_hierarchy_text_excerpt`**.

### Про «процессы 1–10»

- **Разделы ISO 55001** нумеруются **1–10** (полный стандарт): **1–3** — вводные, **4–10** — ядро AMS (HLS).
- **Маршрутизационные процессы бота** — **P00–P07**, из них **P01–P07** соответствуют **ISO 4–10**; **P00** — общий контекст без одного раздела.

## Архитектура оркестрации (2026-05-05)

### Три уровня оркестрации

**NemoClaw (стратегический слой)**
- Модель: Nemotron 120B
- Роль: стратегические решения, сложное рассуждение, выбор пути оркестрации
- НЕ выполняет инструменты напрямую

**PipelineCoordinator (конвейер документов)**
- Порт: 8000
- Роль: координация 7-шагового конвейера документов, цикл самовосстановления
- Маршрутизация через Tool Registry

**ConversationalOrchestrator (интерактивный чат)**
- Модель: Qwen3:14b, порт: 8001
- Роль: интерактивные диалоги, выполнение инструментов
- Поддержка состояния диалога

### Агенты производственной системы

| Агент | Порт | Модель | Функция | Инструмент |
|-------|------|--------|---------|------------|
| **KnomiAgent** | 8010 | Qwen3:14b | Поиск знаний (RAG) | `knomi_search` |
| **DociAgent** | 8020 | Nemotron 120B | Генерация документов | `doci_compose` |
| **CloudAgent** | 8030 | DeepSeek-R1:672B | Валидация качества | `cloud_validate` |

| **TrainiAgent** | 8070 | Qwen3:14b | Оркестрация обучения | `traini_trigger` |

### Вспомогательные сервисы

| Сервис | Порт | Функция |
|--------|------|---------|
| **RepairmanAPI** | 8090 | Автоматический ремонт (Claude Code) |
| **Anthropic Proxy** | 8082 | Шлюз с автоматическим фолбэком моделей |
| **Watchdog Bot** | — | Автоматическое восстановление после перезагрузки |

### 7-шаговый конвейер документов

```
1. KnomiSearch    → поиск релевантных фрагментов знаний (top_k=20)
2. ContextFilter  → фильтрация по качеству, одобрению, типу
3. DociCompose    → генерация документа (Nemotron 120B)
4. CloudValidate  → шлюз качества (DeepSeek-R1:672B, порог 82%)
5. PoliCheck      → одобрение политики для записи в мастер-реестр
6. OmiStore       → сохранение в мастер-реестр
7. Return         → возврат успеха + метрики качества
```

### Цикл самовосстановления

```
ArgusAgent (мониторинг каждые 60с)
    ↓ health_event (CRITICAL/WARNING)
PipelineCoordinator /health_event
    ↓ repairman_trigger
RepairmanAPI (диагностика + патч)
    ↓ repair_plan
PoliAgent (шлюз одобрения)
    ↓ одобренный патч
MainyRepairAgent (исполнитель продакшена)
    ↓ патч применён
ArgusAgent (проверка)
```

### Цепочка автоматического восстановления

**Watchdog Bot** выполняет 4-уровневое восстановление:

**Tier 1: Инфраструктура** (стабилизация 30с)
- ollama, postgresql, redis

**Tier 2: Основные сервисы** (стабилизация 20с)
- anthropic_proxy, pipeline_coordinator, conversational_orchestrator

**Tier 3: Агенты** (стабилизация 15с)
- knomi, doci, cloud, poli, omi, argus, traini

**Tier 4: Боты и воркеры** (финальная проверка)
- repairman_api, telegram_bot, watchdog_bot

Триггер: >30% сервисов недоступны при `AUTO_STARTUP=true`

### Tool Registry

Централизованный реестр инструментов в `ops/logi/tool_registry.py`:
- Все агенты регистрируют свои инструменты
- Оркестраторы вызывают инструменты через `call_tool()`
- Единая точка конфигурации для всех HTTP-эндпоинтов

### Omnirouter (Anthropic Proxy)

Автоматический фолбэк моделей с обнаружением rate limit:

**Цепочка Claude Code:**
- claude-sonnet-4-5 → claude-sonnet-3-7 → claude-opus-4 → local-nemotron

**Цепочка локальных моделей:**
- local-nemotron → llama405b → minimax-m2

Обнаружение: HTTP 429 + паттерны сообщений об ошибках
